2 Officer User Stories (Mobile Application Mode)
2.1 US#1: Officer - Secure Role-Based Login
Story:
As an officer, I want to securely log in to the IVMS mobile application using my officer credentials, so that I can access real-time incidents and respond to events.
Trigger:
When the officer opens the IVMS app and selects â€œOfficer Modeâ€, the system shall display the role-based login screen.
Description:
This functionality provides role-based access for NH&amp;MP field officers within the same Flutter app.
Acceptance Criteria:
The system shall support separate login flow for Officer credentials (distinct from Driver).
The system shall validate officer ID + password or biometric.
Upon successful login, the system shall load the officer dashboard with live incident map.
The system shall restrict access to driver features and enforce role-based permissions.
2.2 US#2: Officer - View Real-Time Incidents and SOS/Crash Alerts on Map Interface
Story:
As an officer, I want to view real-time incidents and SOS/crash alerts on a map interface, so that I can quickly locate and respond to emergencies.
Trigger:
When the officer opens the dashboard after login.
Description:
Live map shows all active incidents.
Acceptance Criteria:
The system shall display an interactive map with pins for all active SOS/crash incidents.
The system shall show vehicle details, location, and severity on tap.
The system shall auto-refresh every 5 seconds.
2.3 US#3: Officer - Receive High-Priority Push Notifications for SOS and Crash Events
Story:
As an officer, I want to receive high-priority push notifications for SOS and crash events, so that I am immediately notified even when the app is in background.
Trigger:
When any SOS or crash is detected.
Description:
Instant alerts for rapid response.
Acceptance Criteria:
The system shall send high-priority push notifications with sound and vibration.
The system shall include incident location and severity in the notification.
