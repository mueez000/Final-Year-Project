
User Stories
3 Headquarters Monitoring Dashboard User Stories (IT Center / Super Admin)

3.1 US#1: HQ Admin - Secure Web-Based Login
Story:
As an HQ admin, I want to securely log in to the centralized IVMS web dashboard, so that I can monitor all buses, incidents, and analytics.
Trigger:
After entering credentials on the web login page, the system shall authenticate and redirect to the dashboard.
Description:
This functionality provides secure access for NH&MP IT Center staff to the centralized monitoring platform.
Acceptance Criteria:
The system shall support web-based login with Admin/HQ credentials (Firebase Authentication).
The system shall display an interactive map with all registered commercial buses in real-time.
The system shall show live incident dashboard with SOS and crash alerts.
The system shall allow configuration of speed zones, hazard zones, and AI parameters.







3.2 US#2: HQ Admin - Real-Time Monitoring of All Registered Commercial Buses on Interactive Map
Story:

3.12 US#12: HQ Admin - View Officers (Officer Management Dashboard)
Story:
As an HQ admin, I want to view the complete list of all NH&MP officers along with their current duties, patrol areas, activity status, and performance metrics, so that I can efficiently manage officer deployment and ensure proper coverage across the motorway.
Trigger:
When the HQ admin clicks the “Officers” tab from the sidebar or dashboard menu, the system shall redirect the admin to the Officers Management page.
Description:
This functionality helps the HQ admin to view all registered officers of NH&MP across all locations/zones, track their assigned duties, current patrol status, and performance so they can make informed decisions about resource allocation and duty management.
Acceptance Criteria:
The system shall display the “Officers” page upon clicking the “Officers” tab from the sidebar.
The system shall display the “Total Number of Officers” on the top.
The system shall display the list of all officers along with the following parameters:
Officer Name
Officer Profile Picture (or default User Profile Icon if not uploaded)
Officer ID / Badge Number
Rank / Designation
Assigned Patrol Area / Zone (e.g., M-2 Salt Range Sector)
Current Duty Status (On Patrol, On Leave, Responding to Incident, Offline)
Last Active Time
Performance Score / Response Time Average (last 30 days)
Number of Incidents Handled (current month)
The system shall display the “User Profile Icon” if any officer has not uploaded their profile picture.
By default, the system shall display all officers of all locations/zones.
The system shall allow the admin to filter officers by Patrol Area, Rank, Duty Status, or Performance Score.
When the admin clicks any filter, the system shall instantly update the list with matching officers only.
The system shall display an “Add New Officer” button at the top right of the page.

3.13 US#13: HQ Admin - Add New Officer
Story:
As an HQ admin, I want to add a new officer to the system so that I can assign them duties, patrol areas, and grant access to the mobile application.
Trigger:
When the HQ admin clicks the “Add New Officer” button from the Officers page, the system shall open the Add Officer pop-up.
Description:
This functionality allows the HQ admin to register a new NH&MP officer, assign initial duties/patrol area, and enable their mobile app access in one streamlined process.
Acceptance Criteria:
The system shall open a modal pop-up titled “Add New Officer” with the following mandatory fields:
Full Name (Type: Alphanumeric, required)
Officer ID / Badge Number (Type: Alphanumeric, unique, required)
CNIC Number (Type: Numeric, 13 digits with dashes, required)
Rank / Designation (Dropdown: Constable, Sub-Inspector, Inspector, etc.)
Phone Number (Type: Numeric, 11 digits, required)
Email (optional)
Assigned Patrol Area / Zone (Dropdown with all defined zones)
Temporary Password (auto-generated or manually set)
The system shall validate uniqueness of Officer ID and CNIC.
The system shall automatically create officer credentials and send login details via SMS/Email.
The system shall display “Officer successfully added and notified” confirmation message.
After successful addition, the new officer shall appear in the Officers list with status “Offline” until first login.
3.14 US#14: HQ Admin - Assign / Edit Officer Duties and Patrol Areas
Story:
As an HQ admin, I want to assign or edit an officer’s duties and patrol areas, so that I can dynamically manage officer deployment according to operational needs and incident hotspots.
Trigger:
When the HQ admin clicks the “Assign Duty” or “Edit” icon next to any officer in the Officers list, the system shall open the duty assignment pop-up.
Description:
This functionality enables the HQ admin to assign specific patrol duties, shift timings, and zones to officers and update them in real-time.
Acceptance Criteria:
• The system shall display a pop-up with the selected officer’s details pre-filled.
• The system shall allow selection of:
Patrol Area / Zone (multi-select if required)
Shift Timing (Start Time, End Time with calendar and time picker)
Duty Type (Patrol, Incident Response, Checkpoint, Rest)
Additional Notes (optional)
• The system shall validate that End Time is after Start Time.
• The system shall display “Duty Assigned Successfully” and immediately update the officer’s status and map view.
• The system shall send a push notification to the officer’s mobile app with the new duty details.
• The system shall maintain a complete audit log of all duty changes.







3.15 US#15: HQ Admin - View Officer Performance & Duty History
Story:
As an HQ admin, I want to view detailed performance reports and duty history of any officer, so that I can evaluate efficiency and make data-driven decisions for promotions or re-assignments.
Trigger:
When the HQ admin clicks the “Performance” or “View Details” icon next to any officer.
Description:
This functionality provides comprehensive analytics for individual officers.
Acceptance Criteria:
• The system shall open a detailed officer profile page or modal.
• The system shall display:
Overall Performance Score
Response Time Statistics
Incidents Handled (with breakdown)
Duty History (calendar view with past assignments)
Violation/Complaint Records (if any)
• The system shall allow filtering duty history by date range.
• The system shall allow export of the report as PDF.














3.16 US#16: HQ Admin - Deactivate / Remove Officer
Story:
As an HQ admin, I want to deactivate or permanently remove an officer from the system, so that I can revoke access when required (transfer, retirement, disciplinary action).
Trigger:
When the HQ admin clicks the “Deactivate” or “Remove” option next to any officer.
Description:
This functionality ensures secure offboarding of officers.
Acceptance Criteria:
The system shall display a confirmation pop-up: “Are you sure you want to deactivate this officer?” with Yes/No options.
On “Yes”, the system shall immediately revoke login access and mark the officer as “Inactive”.
The system shall notify the officer via push/SMS that their access has been revoked.
The system shall preserve all historical data for audit but prevent future logins.

Trigger:
When the admin selects “Log Out”.
Description:
Secure session termination.
